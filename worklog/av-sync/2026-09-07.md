### TL;DR
RODE Wireless Pro の TC（BWF `bext` の `TimeReference`）を鍵に、別録りL/Rとカメラ映像を**サンプル精度で構造対応**させる同期経路を `rehearsal-sync` に追加。ただしカメラ（Ace Pro 2）は外部TC入力を持たず 3.5mm にも LTC が来ないため、**TCで区間対応＋粗オフセットを決め、相関1回で「カメラクロックの定常偏差(skew)」だけを校正**する二段構え。L↔R は TC 差で直接確定。新ツール `bin/advanced/tc-offset`（依存ゼロの BWF パーサ）を追加。実素材で **skew +129.8s（定常＝ドリフトではない）／L↔R TC 差 +1.845s が相関一致 0.2ms／全域 verify ±0.4ms**。commit `d1ca4e3`（main、未 push）。

### 実測で確定した素材の性質
- **音声（RODE Wireless Pro, TC 収録）**: WAV BWF の `bext` チャンクに `TimeReference`＝**ローカル午前0時からの累積サンプル数**が入る。サンプル精度の絶対時刻。L/R は独立レコーダー（TX1/TX2）なので TC 原点は各々だが、両者の差は定常。
- **映像（Insta360 Ace Pro 2）**: 外部TC入力**なし**、3.5mm はプログラム音声のみで **LTC は来ない**。使えるのは `creation_time`（UTC・**1秒量子化**）だけ。→ 映像は「秒精度の絶対時刻」しか持てない。
- **カメラクロック skew**: creation_time と TC の差＝**+129.8s（≒130s、定常）**。これは**ドリフトではなく定常オフセット**（カメラ内蔵時計の設定ずれ）。だから1回の相関で校正すれば全編に効く。

### 実装（bin/advanced/tc-offset 新規）
- 依存ゼロで WAV RIFF を手パースし `bext.TimeReference`（64bit, low/high DWORD）を読む。`TimeReference / sample_rate` で「午前0時からの秒」。
- 映像は `ffprobe` の `format_tags=creation_time`（ISO8601・UTC）→ ローカル秒へ。`--utc-offset` で TZ 補正。
- 出力: `offset = audio_tc_start_sec − video_start_sec`。`--value`（数値のみ）/`--json`/TC も creation_time も無ければ **exit 3**（呼び出し側がフォールバック判定に使う）。

### 実装（bin/rehearsal-sync）
- `measure_tc_offset()` ヘルパで L/R それぞれの TC と映像 creation_time を取得。
- `take.yaml` に `sync.method`（`correlate`｜`tc`）、`sync.tc_utc_offset`、`sync.tc_tolerance` を追加。
- **tc モードの同期ロジック**:
  - `offL` は**相関で求める**（＝カメラクロックの定常 skew を校正する1回の測定）。
  - `offR = offL + (tc_off_R − tc_off_L)` … L↔R は TC 差で直接確定（相関を2回打たない）。
  - L↔R を `tc_tolerance` で**交差検証**（TC 差と相関実測の突合）。
- `channel_drift_correct` は `and not tc_mode` でゲート（TC 素材は定常 skew なのでドリフト補正を掛けない）。
- `--init`: `session_has_tc()` で TC を検出したら生成する `take.yaml` に **`method: tc` を自動記入**。TC 非検出なら従来どおり `correlate`。
- TC が読めない素材では**自動的に相関フォールバック**（回帰しない）。

### 検証結果（Desktop/20260906_合同練習 の一部で通し）
- カメラクロック skew（相関1回）: **+129.8s**（≒130s、事前の目視推定と一致）。
- L↔R: TC 差 **+1.845s**、相関実測との差 **0.2ms**（`tc_tolerance` 内、交差検証パス）。
- 全域 verify（複数地点）: **±0.4ms** で整合。
- 出力（同期済み映像）生成に成功。TC 由来の粗オフセットが正しく、相関は skew 校正の1点だけで足りることを確認。

### 重要な決定と理由
- **TC は「構造化＋粗オフセット」に使い、フレーム精度は相関1回で出す**。Ace Pro 2 が絶対TC（LTC）を持てない以上、映像側の絶対時刻は秒量子化どまり。TC で区間対応と ±秒の粗合わせをし、残差（＝カメラクロックの定常 skew）を相関で1回校正する方が、相関を素材全体に何度も打つより堅牢かつ安価。
- **L↔R は相関でなく TC 差で確定**。両 TX の TC 原点差は定常なので、相関は skew 校正の1点に集約し、L↔R は `offR = offL + (tc_off_R − tc_off_L)` で決めてから TC 差と相関で交差検証。二重測定の誤差累積を避ける。
- **TC 素材ではドリフト補正を無効化**（`and not tc_mode`）。観測された skew は定常オフセットでありクロックドリフト（ppm）ではないため、`atempo` 補正はむしろ害。
- **フォールバックを残す**。TC/creation_time が無い素材（従来のカメラ・音源）は `correlate` にそのまま落ちる。既存ワークフローを壊さない。

### 調べて分かった外部仕様
- **RODE Wireless Pro の TC は WAV BWF `bext.TimeReference`**（64bit・low/high DWORD、単位＝サンプル、原点＝ローカル午前0時）。`iXML` や別チャンクではなくここ。`exiftool` の [System] 時刻とは別物（そちらはファイル mtime 相当）。
- **Insta360 Ace Pro 2 は外部TC入力・LTC 入力を持たない**。3.5mm はプログラム音声のみ。映像の絶対時刻は `format_tags=creation_time`（UTC・**秒量子化**）が上限。→ 映像単独ではフレーム精度の絶対同期は不可能。
- **カメラ内蔵時計のずれは定常**（今回 +130s）。ドリフトではないので1点校正で全編に効く。

### 検討して採らなかった選択肢
- **映像 creation_time だけで同期**：不採用。秒量子化のため最大 ±0.5s 残り、演奏頭出しには粗すぎる。
- **L/R を各々相関で映像に合わせる（相関2回）**：不採用。TC 差が定常に取れるので L↔R は TC 差で確定し、相関は skew 校正の1点に集約。
- **TC 素材にもドリフト補正を掛ける**：不採用。観測は定常 skew でありドリフト（ppm）ではない。
