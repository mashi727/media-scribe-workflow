### 調べて分かった外部仕様（重要・本題）

実素材：`/Volumes/4TB-AFPS/20260823_/`（4案件：20260809_レオケ合同練習[処理済・take.yaml有]、20260822_BBSNK、20260823_みん吹パート練習、20260823_レオケ合同練習）。

**映像（Insta360 ACE Pro 2, MP4）── 絶対時刻あり**
- ファイル名 `VID_<YYYYMMDD>_<sessionHHMMSS>_<globalNNN>.mp4`。`sessionHHMMSS`＝録画セッション開始（**JST・ローカル**）、`NNN`＝カメラ通し番号。
- 埋め込み `creation_time` は **UTC**。例 `2026-08-22T02:42:43.000000Z` ＝ JST 11:42:43（ファイル名 `114243` と一致）。→ **TZ 正規化（+9h）必須**。
- 約30分（1799秒）で自動分割。各セグメントの `creation_time` が連続：058=02:42:43 → 059=03:12:44 → 060=03:42:43 → 061=04:12:42（末尾は短尺 299.5s）。→ **各セグメントの絶対開始が正確に取れる**。
- 取得：`ffprobe -v error -show_entries format_tags=creation_time:format=duration <mp4>`。
- セッション分割はファイル名 stamp の gap で判別。08-22＝11:42:43 / 15:28:37 / 17:19:27 / 17:20:06（末尾2つは**39秒差＝停止・再開＝同一イベント**→gapクラスタリング要）。08-23みん吹＝09:27:44 / 13:20:46（**昼休憩**）。

**音声（RODE Wireless Pro 内部録音, WAV）── 絶対時刻なし**
- **タイムコード／録音日時を一切持たない。** RIFF チャンクは `fmt/cue/PAD/data`（08-22）・`JUNK/fmt/smpl/data`（08-09）で、**`bext` も `iXML` も無し**（先頭・末尾とも走査。`PAD`(32712B) / `JUNK`(52B) / `cue` はすべて全ゼロ）。
- `fmt`：IEEE float・mono・48kHz・32bit（`03 00 / 01 00 / 80bb0000 / align 04 / bits 20`）。
- ファイル名 `NNNNN_TX1_L.wav` / `NNNNN_TX2_R.wav` は通し番号のみ。L/R は同一 index で対応。
- **`exiftool -a -G1 <wav> | grep -iE 'date|time|origin'` で出るのは `[System]`（ファイルシステム）だけ** ＝ SSD へのコピー時刻（例 `2026:08:23 00:48:31`）で録音時刻ではない。埋め込み `[BWF]`/`[iXML]` は空。
- 既存 08-09 の `take.yaml` に「頭合わせは `audio-sync-offset` が自動検出」と明記 ＝ **現行パイプラインは元々 TC 非使用・相関ベース**（裏取り）。

**含意**
- 「音声・映像とも絶対時刻で突き合わせ、相関を省く」版は**この素材では不可**（音声に壁時計が無い）。
- ただし**映像の絶対時刻だけで「イベント/休憩の自動分割・各クリップの絶対配置」は可能**。音声↔セッションの割当と頭合わせは相関（`audio-sync-offset`）が担う。→ 目的（SSDを指す→自動でイベント別の同期・差し替え動画）は**今日の素材でも達成可能**。
- **原本カード**なら、音声のファイルシステム mtime が録音（停止）時刻を保持している可能性（SSD コピーで上書き消失）。`start ≈ mtime − duration`。exFAT には作成時刻＝開始も残る可能性。→ 夜に原本カードで要実測。
- 今後：Wireless Pro の**タイムコード有効化**（RODE Central・2TX ジャム）。ただし **ACE Pro 2 は外部TC入力を持たない**ため、TC でもフレーム精度の自動ロックは不可（カメラは独立クロック）。→ TC は「音声↔映像の割当を一意化＋サブ秒シード」に効き、フレーム精度は相関リファインで詰める。
