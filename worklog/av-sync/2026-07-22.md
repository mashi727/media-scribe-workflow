### TL;DR

FCP を「クリップ同期」専用に使っていた工程を CLI 化。相互相関ベースの同期ツール群
（`audio-sync-offset` / `audio-sync-verify` / `audio-drift-correct` / `audio-merge-stereo`）と
YAML 駆動オーケストレータ `rehearsal-sync` を新規実装し、11 コミット。実素材5テイク
（計 約16時間・約240GB）を処理して全て検証済み。最大の発見は **TX1/TX2 が独立レコーダー
であるため、先にステレオ結合すると左右が数十秒ズレる**こと。各chを映像へ個別同期してから
結合する設計に作り替えた。

### 重要な決定と理由

- **各chを映像へ個別同期してから結合**（`571eba1`）— TX1/TX2 は独立レコーダーで開始時刻も
  クロックも別。先に結合すると左右が数十秒ズレる。両chを共通の映像クロックに固定することで
  独立開始も相互ドリフトも自動吸収される。
- **アライメントを実サンプルとして焼き込む**（`adelay=NS` / `atrim=start_sample`）— `-itsoffset`
  だと PTS/エディットリスト依存になり、再抽出時に無視されて残差が出た（実測 -2.478s）。
  サンプル焼き込みなら全環境で確定的。
- **ドリフト補正は atempo を採用**（asetrate ではなく）— 物理的には varispeed が正確だが、補正量が
  ppm オーダーで音程変化は不可聴。かつ atempo は正確な浮動小数係数を取れる（asetrate は整数SR
  制約で ppm 分解能が出ない）。
- **ドリフト係数の符号は自動決定** — `f = 1∓slope` の両候補で残差を実測し小さい側を採用。
  導出の符号ミスに依存しない堅牢設計。
- **検証は2段構え** — 全体相関スコア＋複数地点の整合。スコアだけでは「一部だけ一致」を
  見抜けないことを実測で確認したため（後述）。
- **`base: audio`（黒画面フィル）は見送り** — ユーザー判断。「録音を止め忘れる」レアケース
  のために恒久的な複雑さを抱えるのは割に合わない。試作2ツールは未コミットで保留。
- **疎結合の切り分け原則＝「参照先で決まる」** — L↔R 同期は映像を一切参照せず音声内で完結する
  ためオーディオ側（`rehearsal-finalize-audio`）の責務。音声↔映像同期はメディア横断のため
  `rehearsal-sync` の責務。この原則により loudnorm の位置づけ問題も整理できた。
- **numpy のみに依存（scipy を排除）** — PATH 上に scipy 入り/無しの python3 が混在しており
  `env python3` 経由で落ちた。WAV読込は標準 `wave`、相関は `numpy.fft` に置換。

### ハマった点・エラーと回避策

**1. scipy が env python3 で見つからない**
```
ModuleNotFoundError: No module named 'scipy'
```
→ 原因: PATH 上に scipy 入りの python3 と homebrew python3 が混在。
→ 解決: scipy 依存を排除し numpy のみに（`wave` ＋ `numpy.fft`）。自己完結性も向上。

**2. `-itsoffset` がサンプルとして焼き込まれない**
検証で残差 -2.478657s。mp4 のエディットリスト/PTS 依存になり、再抽出時に無視されて先頭に寄る。
→ 解決: `adelay=<N>S:all=1` / `atrim=start_sample=<N>` で実サンプル化。残差 **-0.000000s**。

**3. 大きな開始オフセットでドリフト測定が破綻**
```
audio-drift-correct: error: drift -3260.7 ppm exceeds --max-ppm 1000.0 (測定異常の可能性)。--force で強行可。
```
→ 原因: 冒頭/終端の測定窓を映像と音声で**同じ index** で切っていたため、全体オフセット
  （実測 **-168.62s**）が窓幅(120s)を超えると窓が重ならず相関が壊れる。スコアも 6.8/8.3 と低下。
→ 解決: 間引いた全長相関で粗い全体オフセットを求め、音声側の窓位置をシフトしてから局所測定。
  修正後スコア **245.3/179.4**、drift **-11.09 ppm**（妥当）、補正後残差 -0.001 ppm。
→ 教訓: `--max-ppm` ガードが誤補正を防いだ。安全機構の設計が正しかった。

**4. スコアが高くても「一部だけ一致」を見抜けない（最重要）**
時間を空けて撮った3クリップを連結した映像で、全体相関スコアは **L=84.3 / R=279.4** と高いのに、
clip2/clip3 には全く別の音声が乗る（score 4.7〜6.7）。しかも `rehearsal-sync` は "done" と正常終了。
→ 原因: 全体相関は「自信のあるピークが1つあるか」しか見ない。clip1 の60秒が強く一致するだけで
  高スコアになる。
→ 解決: `audio-sync-verify` を新規実装。N地点で局所相関し、1つでも外れれば非ゼロ終了。
  ギャップありケースで 5地点中3地点 NG を検出し、出力を作らず中断できるようになった。

**5. 黒画面と実クリップの無劣化 concat（試作時）**
```
[vost#0:0/copy @ ...] Non-monotonic DTS; previous: 749000, current: 191488; changing to 749001.
```
出力尺が 20s のはずが 58.59s に暴走。
→ 原因A: `-preset ultrafast` が `-profile:v high` を上書きし Constrained Baseline に落ちる。
→ 原因B: **time_base 不一致**（カメラ 1/30000 or 1/50000 vs libx264 既定 1/12800）。比 749000/191488 ≈ 3.906 = 50000/12800。
→ 解決: `-preset veryfast` ＋ `-video_track_timescale <カメラのtimescale>`。尺 20.000s、デコードエラーなし。

**6. 検証方法そのものの誤り（片ch vs ミックス）**
出力の片チャンネルだけを映像スクラッチ（両TXのミックス）と相関させると +17〜26ms ずれて見えた。
→ 原因: もう一方のTXがクロストーク的バイアスになる。
→ 正しい測り方: **出力ステレオのミックス vs 映像のミックス**。実測 **+0.000001s**。

**7. take.yaml 未作成のまま実行**
```

```
→ 20260704 用に作った設定を 20260719 用と混同していた。当該フォルダに作成して解消。

**8. audio-concat の 32bit float 制約**
```
audio-concat: error: ... is not 32-bit float (sample_fmt=s16); pass --any-format to override
```

### ユーザーからの指示・好み(後続で尊重)

> このツールは、同期を取るだけにしたいので、他の機能は不要ですね。

> 今回のように、休憩時無音という状況はほとんどないですし、録音を止め忘れるという、レアなケースが重なった結果の状況なので、それに対応するための機能は不要です。

> 同期という機能で見るか、オーディオという扱う対象で区切るかという疎結合をどこで区切るか問題ですね。

> rehearsal-finalize-audioで、LR同期のステレオ化をしたほうが、基礎練抽出では便利なんですけどね。

> そうなんです。基礎練習時のビデオの録画ボタンを押し忘れていたんですね💦

> 既存の動画編集ツールを使えば、基礎練部分は残すことができて、AM,PM別ファイルの動画ができても支障なさそうです。

方針の要点:
- **同期に徹する。機能追加には保守的**。レアケース対応より単純さを優先。
- 疎結合の切り分けに強い関心。対象軸（オーディオ/映像）で切る発想を持っている。
- 実素材で検証してから採用する姿勢。
