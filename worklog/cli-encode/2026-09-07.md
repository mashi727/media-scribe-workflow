### TL;DR
ワークフローを「**chaptr＝章立て作成専用の単一ソース GUI**／**エンコードは CLI（vce-encode）**」へ再整理。chaptr から**エンコード/書き出しサブシステムと複数ソース束ね機能を一掃**（Stage A/B, 6 commit）、`.vce.json`（多ソース PROJECT 形式）を退役させ **chaptr の章立て `.txt` 一本**に。`vce-encode`/`vce-split` が `.txt` を入力に取り、`--source`/`--fhd`/`--youtube-chapters` で**オリジナル動画→FHD YouTube 用動画**を CLI で出力できるように拡張。プロキシは廃止（50GB の FHD master でも再生・編集に支障なし＝**総エンコード1回**に集約）。副産物として `static_ffmpeg`（2022 evermeet x86_64/Rosetta）が長尺 `hevc_videotoolbox` で失敗する根因を突き止め、システム ffmpeg 優先へ修正。media-scribe: `61e91a2`/`5b0b142`（main）。chaptr: branch `refactor/cli-encode-single-source`（6 commit、**未 merge/未 push**）。

### 経緯（なぜ整理したか）
ユーザーの状況変化を受けた再設計:
> chaptr にエンコードの UI をつけていますけど、これは中途半端ですね。…エンコードはコマンドラインから行うのが良さそうです。
> この機能をバッサリ削除しますかね。あと、自分が録画をするようになってから複数録画を束ねる機能も必要性を感じなくなりました。これは、1年前くらいに、分割された録音をもらったときに、それを束ねるのが目的で作成したものですけど、今となっては使わないですね。

→ **束ね（multi-source）はもう不要**。`.vce.json` はその多ソース前提の PROJECT 形式なので存在意義を失う。エンコード進捗表示の利便はあるが GUI に抱えると中途半端。**単一目的ツールを組み合わせる本リポジトリの思想**（配管）に戻す。

プロキシ方針も:
> 50GB の動画も問題なく再生などできていたので、プロキシを使うのをやめましょうか。エンコードの手間が増えるだけですものね。

→ **プロキシ廃止**。`rehearsal-sync --init` の既定を `-c:v copy`（FHD master 直出し）にし、GPU 軽量プロキシ（`output.video`）はコメントのオプションへ格下げ。**総エンコードは vce-encode の1回だけ**（FHD master → chaptr で章立て → vce-encode で YouTube 用）。

### 重要な決定と理由
- **`.vce.json` を退役、chaptr `.txt` 一本化**。`.vce.json` は多ソース束ねのための PROJECT 形式で、束ね機能が不要になった今は構造だけが残る負債。単一ソースなら `.txt`（source ヘッダ＋時刻＋タイトル）で必要十分。
- **エンコードは GUI から CLI へ**。進捗表示の利便より「単一目的の配管」を優先。chaptr は章立て作成に専念。
- **プロキシ廃止＝総エンコード1回**。FHD master は 50GB でも実用上問題なく再生・編集できるため、プロキシ用の追加エンコードは純損。`rehearsal-sync` は FHD master を直出し、最終 YouTube 版のみ `vce-encode` で1回焼く。
- **ffmpeg はシステム優先**。`static_ffmpeg` は 2022 の evermeet x86_64 ビルドで、Apple Silicon では Rosetta 経由となり長尺 `hevc_videotoolbox` で落ちる。同梱は「無い環境のフォールバック」に限定する。

### 調べて分かった外部仕様
- **`static_ffmpeg`（pip）は古い evermeet x86_64（2022）を持ってくる**。Apple Silicon では Rosetta 実行になり、長尺の VideoToolbox ハードウェアエンコードで失敗する。homebrew の native arm64 ffmpeg 8.1.1 は問題なし。→ ツールは常に `shutil.which` を先に見る。
- **chaptr の `.txt` 章立て書式**: `# source: <video>` ヘッダ＋`H:MM:SS.mmm title` 行。`--` 接頭のチャプターは**除外/カット**扱い。`vce-encode`/`vce-split` が同書式を単一ソース project として解釈できる。
- **chaptr に `SourceListWidget` が 2 実装あった**（`main_workspace.py` inline が実使用、`ui/widgets/source_list.py` は未使用の重複）。片方だけ育つと将来事故るので dead-dup を削除。

### 検討して採らなかった選択肢
- **`--init` で FHD master と GPU プロキシを同時出力**：一時検討したが不採用。プロキシ自体を廃止したので二重出力の意味がない（ユーザー提案の「もしくはプロキシをやめる」を採用）。
- **chaptr にエンコード進捗だけ残す**：不採用。中途半端さの温存になる。CLI に一本化。
- **`.vce.json` を単一ソースでも残す**：不採用。`.txt` で足り、二形式並存は保守負債。

### ハマった点・エラーと回避策
- **`vce-encode -q 0` が失敗**（swscaler `deprecated pixel format (yuvj420p)`＋非0終了）。当初 pix_fmt/ディスク容量を疑ったが、**根因は `static_ffmpeg`（Rosetta 実行の 2022 ビルド）**。→ システム ffmpeg 優先へ修正（`5b0b142`）。
- **Stage B を subagent に投げたら 600s 無進捗で停止**（Dropbox 越し `grep -r` タイムアウトが濃厚）。→ Stage B を手動実施。
- Dropbox 上の `grep -r`／`py_compile` 全走査／PySide import 検査が**軒並みタイムアウト**。→ 単一ファイル grep・Read・対象限定 `py_compile`・sandbox off を使い分け。
- scratchpad への `rm -rf` が権限ゲートで拒否。→ 単一ファイルの `rm -f`。
- chaptr の Pyright 警告（`QCoreApplication.setFont`／`_MEIPASS`／`mousePressEvent` 引数名／`QStyleOptionViewItem.rect`／None メンバアクセス）は**既存の PySide6/Pyright ノイズ**で、今回の編集起因ではないと確認。
